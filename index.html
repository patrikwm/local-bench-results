Can a gaming PC replace a paid AI coding subscription?

The plan

On this PC every model climbs level by level, all models together: a level is a filter, so only models that pass it get the next, more expensive one. The rented GPUs ran one model straight up the ladder each (paid by the hour); those runs are finished.

  1. 1 · Level 128 small tasks, every model. Done for all PC models.
  2. 2 · Level 2Real open-source projects, for the models that passed L1. Under 65 % at L1: a 60 % probe first.
  3. 3 · Sysadmin S1–S3Scripts, containers, troubleshooting, for the models that passed L2.
  4. 4 · Level 3Fresh hard tasks, only for models with 90 %+ of their L2 pairs.
  5. 5 · LeftoversUnfinished or blocked runs (Devstral L1, gpt-oss-120b S2 re-run, engine comparisons, Laguna, Qwen3 14B), maybe skipped.
  6. 6 · FinalsThe top 4–6 models: 3 fresh attempts on all of L1 and L2, on this PC only, clean conditions.

The ladder

Each model climbs from small tasks to one-night builds. A task with one agent is a pair; a pair passes when 2 of 3 attempts pass, and a level passes at 50 % of its pairs. A model stops at the first failed level; one that passes with under 65 % runs the next level as a probe first, and L3 needs 90 % of the L2 pairs.

Quick jobs

One prompt, one answer, no agent: fix Markdown, extract JSON, write a commit message. Every answer is checked exactly. The goal is a routing table: the smallest model that is good enough for each kind of job.

Not selected for Level 3

L3 costs the most time, so only models with 90 %+ of their L2 pairs get it. This is a budget rule, not a verdict: 90 % of 28 pairs is 26, so one pair can decide it.

How this is tested

How to read the results

  • Hidden tests decide. Pass or fail comes from tests the agent never sees, not from an AI judge. Test-writing tasks pass when the agent's tests pass on the correct code and catch at least 80 % of planted bugs.
  • Few distinct tasks. L1 has 28 tasks in 7 languages. Thousands of attempts measure how reliably a model solves those 28, not thousands of different problems.
  • Rows marked rented ran their engine on a rented GPU. The faster GPU can turn a time-out into a pass, so they preview a model rather than describe this PC. The rented Strata rows ran with a 64k context (the PC rows 128k), so some long attempts hit the context limit.
  • Invalid runs are removed, not hidden. Runs broken by the setup (wrong engine, server power-off, harness bug) move to a superseded folder with a note on why, and run again. Grader fixes so far: S2 Docker checks and test-writing tasks (2026-10-23, 28 attempts re-graded).
  • Exact files. Every model is pinned to a file and revision. Strata Coder IQ1_M runs the revision pinned by Strata v0.1.44.1 (2026-09-29), before the quantizer's 2026-10-17 update.

Setup

  • Languages: Python, TypeScript, Java, C#, C++, Rust, Go. Four tasks each at L1 (two bug fixes, a feature, a test suite), two at L2 in real open-source projects.
  • Agents: Pi 1.3.0 and OpenCode 2.0.32, pinned, in a WSL sandbox with no network except the model.
  • Engines: Strata 0.1.44.1 (biggest MoE models, experts streamed from RAM) and llama.cpp b11685. Every result records engine, version, flags, quant and model files.
  • Limits: L1 20 min per attempt, L2 45 min, L3 3 h. Up to 32K tokens per answer. Looping or idle runs are stopped early; slow runs are not.
  • Measured: wall time, requests, tokens, cache hits, decode speed, GPU power (nvidia-smi), CPU package power (Intel RAPL), VRAM, RAM, energy per solved task.
  • Hardware: Intel i7-13700KF, 64 GB DDR5-5600, NVIDIA RTX 4080 16 GB, Windows 11 + WSL2. Also a MacBook Pro M1 Max 64 GB for speed tests.

Why it is tested this way

  • The result is what runs on this PC. The question is whether a normal gaming PC can replace a cloud subscription, so the main results are always this machine, within the time limits.
  • Majority stop saves energy. When attempts 1 and 2 agree, attempt 3 cannot change the verdict, so it is not run. The table then says 2/2, never 3/3.
  • Screening first, full runs for finalists. Every model gets one probe attempt per task; under a quarter solved and the rest is skipped. The 4 to 6 finalists get 3 fresh attempts on all of L1 and L2.
  • Each model runs as its maker intends. Sampling settings come from the model card. Settings of our own are only ever a separate experiment.
  • Hard tasks are fresh and fixed in advance. L3 tasks were written after the models were frozen. Their hashes are published before any model runs them.
  • Grading is objective and cheap. About 2 seconds per attempt, so it stays on the PC.
  • What is not claimed. Related tasks are not independent evidence. Repetitions measure consistency, not breadth. 28 L1 tasks say something about these tasks, not about a whole language.
