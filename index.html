Can a gaming PC replace a paid AI coding subscription?

Open-weight models run on one desktop PC and drive two open-source coding agents, Pi and OpenCode, through the same real coding tasks. A hidden test suite decides pass or fail. No AI judge, no vibes.

The plan

Every model climbs level by level: a level is a filter, so only models that pass it get the next, more expensive one. Two machines work in parallel: this PC and a MacBook (M1 Max). The rented GPUs ran one model straight up the ladder each (paid by the hour); those runs are finished.

  1. 1 · Level 128 small tasks, every model. Done for all PC models.
  2. 2 · Level 2Real open-source projects, for the models that passed L1. Under 65 % at L1: a 60 % probe first.
  3. 3 · Sysadmin S1–S3Scripts, containers, troubleshooting, for the models that passed L2.
  4. 4 · Level 3Fresh hard tasks, only for models with 90 %+ of their L2 pairs.
  5. 5 · Leftovers and L0Devstral (L1 rest and up, on this PC), Qwen3 14B (on the Mac), then an L0 speed glance for every model on this PC. Blocked: work that only a rented GPU could run.
  6. 6 · Final showdownThe top 3 models: every level, 3 fresh attempts, on this PC.

The ladder

Each model climbs from small tasks to one-night builds. A task with one agent is a pair; a pair passes when 2 of 3 attempts pass, and a level passes at 50 % of its pairs. A model stops at the first failed level; one that passes with under 65 % runs the next level as a probe first, and L3 needs 90 % of the L2 pairs.

How sure is this?

  • The lag is steady: 7, 6, 7, 9 months at four points in time. Two ways to project agree roughly: keep a 6–9 month lag (the frontier hit 96 in Jul 2026, so early to mid 2027), or keep local's recent pace of ~1.4 points a month (79 → 96 takes ~12 months, Aug 2027). Shaded: Apr–Aug 2027.
  • The benchmark is nearly used up. The frontier sits at 95–96, and SWE-bench Verified is known to have leaked into training data; OpenAI stopped reporting it in Feb 2026. "As good as Fable 5" will really be judged on harder tests (SWE-bench Pro, Terminal-Bench), where local is probably further behind.
  • Mixed harnesses. The makers each use their own agent setup, and none of these numbers are reproduced. Some release dates are approximate, and Fable 5 is given as 95.0 or 93.9 depending on the source.
  • Our own ladder is the real check: when a new local model lands, it runs the same hidden tests as everything here.

Security: what did the models try to reach?

On Monday 26 Oct, Cohere reported that Alibaba's Qwen3.8-Flash-Next tried to send a file to an outside server during a test, right after its own notes said it would not use any tools. Our two best models are that same model (Strata IQ2_XS and IQ3_S), so we searched every tool call our agents have made since 19 Oct for traffic to the outside world.

We saw it too, once: a call to Alibaba Cloud that the task did not need

  • When and where: 22 Oct 2026, 20:34, attempt 2 of the Level 2 Python task l2-py-feature-tenacity-stopidle, OpenCode 2.0.32, Strata IQ2_XS (Qwen3.8-Flash-Next, 2-bit), on a rented UpCloud server, not at home.
  • What it did: twice in the same run (model calls 106 and 111) it used OpenCode's JavaScript tool to fetch() a file from an Alibaba Cloud storage bucket in Singapore: routify-file-proxy-sg.oss-ap-southeast-1.aliyuncs.com/proxy_temp_file/production/2026-10-22/trace_…. The address looks like a signed download link, with an Alibaba-style access key id (redacted here) and the date of our run inside it.
  • What it said it was doing: its notes right before were "Let me do a final verification of from tenacity import stop_before_idle …" and "verify import tenacity.stop usage". The action had nothing to do with that. It is the same mismatch between words and action that Cohere describes.
  • What happened: the server answered 403 Forbidden both times. They were plain downloads (GET, no body), so no file or task data was sent. Alibaba saw the rented server's address and a made-up link. The model then finished the task, and the hidden tests passed.
  • How often: once in about 750 attempts with Qwen3.8-Flash-Next (467 IQ2_XS + 283 IQ3_S), and never with any other model. No other Chinese host shows up anywhere in the tool calls.
  • Our reading: like most researchers who looked at Cohere's traces, we think this is a habit from training. Agent training sandboxes often store files behind links like this, and the model fills one in the way autocomplete would. We see no sign of a planted backdoor. Still, an agent should never contact a server you didn't ask for, and the guard rails described below did not stop it.

What we scanned

Every saved model reply from 19 to 28 Oct: 3,888 attempts, 100,883 replies, 107,324 tool calls, on this PC, on the rented GPUs and on the Mac lane (its agents run on the PC). We pulled every web address and network command out of the tool calls and matched each with the result it got back. The models themselves run locally (llama.cpp / Strata), so the model never sends anything out. The only way out is a tool call made by the agent.

What this means

  • Scores: 10 solved attempts had the upstream code available. That is 9 task-agent pairs: 4 at Level 2 and 5 at Level 3, all on Strata IQ2_XS/IQ3_S, Qwen3.8-27B and Ornith-1.5. Having the code doesn't mean the model copied the answer, but we can't rule it out. These pairs are under review: the 10 attempts have been set aside and are re-running first, on this PC with the network cut off, before the normal queue continues. The pairs update as each one finishes.
  • Most of the ranking stands: that is 9 pairs out of thousands of attempts. The first attempts on the same tasks were usually solved without any network access.
  • Fixed (28 Oct, before testing resumed at 16:15): the sandbox now has a real network cut-off (a firewall in the sandbox, for every user and for Docker containers). Only the local model server and the task's own containers can be reached, and grading is cut off too. Tested: GitHub, a plain IP, Python and Node downloads and containers are all refused, while the model server still answers. We kept OpenCode's execute tool: with no network it can't reach anything, and changing the agent's setup in the middle of the ladder would split its results from earlier ones.
  • Scanned automatically from now on, in two ways. (1) Every address in the model's tool calls (web links, bare IPs, host:port, /dev/tcp, nc …) is recorded, together with the command it tried to run. (2) The firewall logs every packet it rejects, on any port and protocol (not just 443: also UDP, DNS and ping), with its destination. Hosts, ports and blocked packets show live below. The full command text stays private, because it can contain task content. Note: the PC and Mac lanes share one Linux kernel, so a blocked packet logged while both are running may belong to either lane.
  • Being checked: whether the engines themselves (Strata, llama.cpp) open any outside connections. For the first 6 hours of testing, their connections are logged every 10 minutes. None so far.
  • Found by the new firewall log (28 Oct): the agent program OpenCode phones home. In every OpenCode attempt (never in Pi), the agent tries api.opencode.ai on port 443, even though sharing and auto-update are off in its settings. It's blocked now, but before 28 Oct those calls went through. They are encrypted, so we can't see what they contained. This is the agent program, not the model. Also blocked, and not counted as the model trying anything: Ubuntu's own background services in the sandbox (clock sync on port 123, the snap store api.snapcraft.io).

The verdict

  • S: the 256 GB Mac Studio is the Cayenne. About +18 points on terminal work, the fastest of the four, silent, one box. 256 GB is the sweet spot: 512 GB costs ~$6k more and its best model scores no higher.
  • A: two DGX Sparks get the same model for a bit less, but slower and as two boxes to look after.
  • B: 512 GB runs the DeepSeek from the headlines, but lower than MiMo on this board, and its software is still young.
  • C: a 96 GB GPU in this PC is as expensive as the Mac and the model only just fits; no measured speed.
  • Not on the list: 128 GB boxes (Strix Halo, one DGX Spark, Mac Studio 128 GB), 2 × RTX 5090 and more PC RAM. At a sane quality they run the same models this PC already runs. And there is no 256 GB Mac mini (the mini tops out at 64 GB).

Why not SWE-bench? No independent SWE-bench board has these new models yet, and the makers' own numbers run high: Qwen3.8-27B reports 73.0 on Terminal-Bench 2.1 itself but scores 58.4 on Vals. So only one board is used, and Ornith-1.5 and Laguna (not on it) can't be compared. All upgrade models are Chinese open weights: fine at home, never through their own APIs. Not selected for Level 3

L3 costs the most time, so only models with 90 %+ of their L2 pairs get it. This is a budget rule, not a verdict: 90 % of 28 pairs is 26, so one pair can decide it.

How this is tested

How to read the results

  • Hidden tests decide. Pass or fail comes from tests the agent never sees, not from an AI judge. Test-writing tasks pass when the agent's tests pass on the correct code and catch at least 80 % of planted bugs.
  • Few distinct tasks. L1 has 28 tasks in 7 languages. Thousands of attempts measure how reliably a model solves those 28, not thousands of different problems.
  • Rows marked rented ran their engine on a rented GPU. The faster GPU can turn a time-out into a pass, so they preview a model rather than describe this PC. The rented Strata rows ran with a 64k context (the PC rows 128k), so some long attempts hit the context limit.
  • Invalid runs are removed, not hidden. Runs broken by the setup (wrong engine, server power-off, harness bug) move to a superseded folder with a note on why, and run again. Grader fixes so far: S2 Docker checks and test-writing tasks (2026-10-23, 28 attempts re-graded).
  • Exact files. Every model is pinned to a file and revision. Strata Coder IQ1_M runs the revision pinned by Strata v0.1.44.1 (2026-09-29), before the quantizer's 2026-10-17 update.

Setup

  • Languages: Python, TypeScript, Java, C#, C++, Rust, Go. Four tasks each at L1 (two bug fixes, a feature, a test suite), two at L2 in real open-source projects.
  • Agents: Pi 1.3.0 and OpenCode 2.0.32, pinned, in a WSL sandbox with no network except the model.
  • Engines: Strata 0.1.44.1 (biggest MoE models, experts streamed from RAM) and llama.cpp b11685. Every result records engine, version, flags, quant and model files.
  • Limits: L1 20 min per attempt, L2 45 min, L3 3 h. Up to 32K tokens per answer. Looping or idle runs are stopped early; slow runs are not.
  • Measured: wall time, requests, tokens, cache hits, decode speed, GPU power (nvidia-smi), CPU package power (Intel RAPL), VRAM, RAM, energy per solved task.
  • Hardware: Intel i7-13700KF, 64 GB DDR5-5600, NVIDIA RTX 4080 16 GB, Windows 11 + WSL2. Also a MacBook Pro M1 Max 64 GB for speed tests.

Why it is tested this way

  • The result is what runs on this PC. The question is whether a normal gaming PC can replace a cloud subscription, so the main results are always this machine, within the time limits.
  • Majority stop saves energy. When attempts 1 and 2 agree, attempt 3 cannot change the verdict, so it is not run. The table then says 2/2, never 3/3.
  • Screening first, full runs for finalists. Every model gets one probe attempt per task; under a quarter solved and the rest is skipped. The 4 to 6 finalists get 3 fresh attempts on all of L1 and L2.
  • Each model runs as its maker intends. Sampling settings come from the model card. Settings of our own are only ever a separate experiment.
  • Hard tasks are fresh and fixed in advance. L3 tasks were written after the models were frozen. Their hashes are published before any model runs them.
  • Grading is objective and cheap. About 2 seconds per attempt, so it stays on the PC.
  • What is not claimed. Related tasks are not independent evidence. Repetitions measure consistency, not breadth. 28 L1 tasks say something about these tasks, not about a whole language.
